# 多目标导航阶段总结

更新时间：2026-08-22
当前冻结 profile：`adaptive_goal_line_045`

## 本阶段完成内容

本阶段先固定自适应目标线 profile 完成双目标三次基线验证，再执行五点闭环三次
正式回归。五点任务为：

```text
M -> A -> B -> C -> D -> M
```

五点三次实验全部完成，15 个导航分段均返回 `status=4`。总成功率为 `3/3 = 100%`，
分段成功率为 `15/15 = 100%`；三次物理 contacts 过滤地面后均没有机器人与障碍物
的接触。完整表格和图像见
[五点闭环导航实验记录_2026-08-22.md](../06_五点闭环与顺序验证_2026-08-22/五点闭环导航实验记录_2026-08-22.md)。

## 当前可完成的任务

当前系统已经完成以下仿真闭环：

- Gazebo 中使用 RGB-D 相机和里程计运行 RTAB-Map 在线 SLAM；不需要先单独建图。
- Nav2 接收当前目标，global costmap 和 local costmap 由地图与 RGB-D 点云共同更新。
- `GoalLineSmacPlanner` 在每次规划调用中根据当前起点、当前目标和实时 costmap 搜索，
  对起点到目标的直线给予软偏好，同时绕开 lethal obstacle 和 footprint 不可行区域。
- RPP 根据 Smac 路径的前视点连续跟踪，并根据曲率、代价和前向碰撞预测调速。
- collision monitor 对 `/cmd_vel` 进行最后的 slowdown/stop 过滤，底盘最终接收
  `/cmd_vel_safe`。
- 连续多个目标可以独立计时、分段记录并生成 Gazebo 真值与 RViz 风格的左右对比图。

这已经是“当前仿真场景中的 RGB-D 在线建图、多目标点到点导航和障碍绕行”功能闭环，
不再是只完成一小段固定路线的演示。

## 结果判读

五点三次总 wall 时间为 `283.769 s`、`282.744 s`、`299.175 s`，平均
`288.563 +/- 7.516 s`；总轨迹长度平均 `51.919 +/- 0.877 m`。run_02 是这三次
中的最快样本，但当前只有一个 profile 通过五点三次验证，所以只能冻结为可靠基线，
不能称为所有参数中的全局最优。

末端 XY 诊断值范围为 `0.097--0.246 m`。Nav2 action 成功率和 Gazebo 物理 contacts
是本阶段的硬验收指标；脚本结束时的最后 TF/Gazebo 采样误差受消息时序和地图坐标
影响，应作为附加诊断指标，而不是替代 action 内部 goal checker。

## 方法边界

`adaptive_goal_line_045` 已经移除了 v4 中当前 large 场景的固定 world 坐标走廊：

- `side_bias_enabled=false`；
- `side_bias_target_schedule_enabled=false`；
- 每一个新的目标都重新计算目标线软代价；
- 真实障碍的绕行方向仍由当前已观测的地图、RGB-D obstacle layer 和 Smac 搜索决定。

因此这不是“背诵 M->A->B->C->D->M 路线”。换地图或换目标后，它不会知道未知区域中
尚未被相机看到的障碍；它只能依据已建地图和当前深度观测规划。未知环境中的完全
遮挡、窄通道、反光/无纹理表面、深度掉帧和目标不可达仍可能导致停顿或失败。

## 下一步顺序

### 1. 先做跨场景仿真

保持本文件冻结参数不变，只改变一个场景因素：起点/目标、障碍栏位置、箱体数量或
通道宽度。每个新场景至少做三次独立重启，继续记录成功率、wall 时间、路径长度、
末端误差、双视图轨迹和 contacts。新场景失败时，不要把失败结果删除；先建立新的
profile 和失败分析。

### 2. 再接入真实 D435i

进入真实设备的条件是：仿真跨场景至少能证明 profile 不依赖固定世界坐标，且真实
底盘已经提供稳定的 `odom -> base_link`。硬件阶段先做近距离目标和静态障碍验证，
再做在线建图，最后才切换保存地图的 localization 模式。

真实 D435i 需要重新测量相机相对底盘的 `x/y/z/pitch`，检查 USB 带宽、深度帧率、
TF 时间戳、底盘速度接口和 `/cmd_vel_safe` 接入。仿真和真实 launch 不能在同一个
ROS domain 同时运行，因为二者会抢占 `/camera`、`/rtabmap` 和 Nav2 节点名称。

### 3. 最后才做速度优化

当前先把 0.45 m、RPP 0.28 m/s、前视 0.62--1.20 m 和 GoalLine 参数冻结。后续若
要追求更短时间，必须从该冻结提交复制新 profile，每次只改一个因素，并要求三次
成功率仍为 100% 且无非地面 contacts；不能以一次漂亮轨迹替代三次统计。
