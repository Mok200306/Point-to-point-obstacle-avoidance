## 4. 结果分析

### 成功性和安全性

三组均为 `3/3` 完整 run 成功，合计 `45/45` 目标段返回 Nav2 `status=4`。六个新 run 的 Gazebo contacts 原始消息数为 `788,872--805,068`，原始闭环为 `698,851--762,921`；这些数值是传感器/物理接触话题的采样消息数量，不能直接当作碰撞次数。三组九次 run 过滤 `ground_plane` 后均无非地面接触对，因此在该仿真场景中获得了 `0/9` 非地面接触证据。

### 速度和路径长度

实验 1 的平均轨迹比原始闭环短约 `2.205 m`（约 `4.25%`），但平均 wall 长约 `8.086 s`（约 `2.80%`）；实验 2 的点位顺序本身包含更长的跨场景段，平均轨迹比原始闭环长约 `6.086 m`（约 `11.72%`），平均 wall 长约 `37.273 s`（约 `12.92%`）。因此不能只按总 wall 排名三组，顺序改变了任务几何长度；在同一段目标之间比较时，才有调参意义。

实验 1 的轨迹标准差为 `0.041 m`，实验 2 为 `0.023 m`，说明在这两种顺序下路径长度重复性较好。原始闭环的长度标准差较大，主要来自 `run_03` 的实际绕行偏差。

### 末端误差

三组所有段的 XY 误差均处于当前 goal checker 的 `0.12 m` 附近量级，个别段的记录末端误差可高于该值，因为这里保存的是结束时 TF/Gazebo 采样诊断值，而 `status=4` 是 Nav2 action 的最终验收状态，二者不是同一个时间点或同一个判据。新顺序实验 1 的误差均值最低；实验 2 的最大误差 `0.222 m` 出现在 `C->D`，但该段仍返回 `status=4` 且无物理接触。

### 是否证明实时规划

证明强度如下：

1. 起点分别变成 C 和 B，第一段目标分别变成 A 和 M；
2. 每段都是新的 action，且 trial 从当前实际位姿创建记录；
3. `adaptive_goal_line_045` 明确关闭 `side_bias` 和世界坐标 schedule；
4. 六张新图中的彩色轨迹随顺序改变，黑色虚线也随每段 start/goal 改变；
5. 每次 run 使用 `reset_db=true`，没有依赖上一轮保存地图回放。

因此可以把当前结论写为：在当前大场景和仿真 RGB-D 条件下，算法已通过三种点位顺序的在线建图、多目标、点到点避障闭环验证。它不是“提前知道所有障碍物”的固定路线，也不是对任意未知环境都保证成功；尚未观测到的障碍仍只能在深度相机看到后进入代价地图。

## 5. 统一结论

本场景的功能验证可以冻结为：`adaptive_goal_line_045` 在三种五点闭环顺序下 `9/9` run 成功、`45/45` 段成功、`0/9` 过滤后非地面物理接触。后续不应继续在同一场景无目的地扩张参数；下一阶段应按跨场景指南一次改变一个环境因素，重新完成三次独立回归。
