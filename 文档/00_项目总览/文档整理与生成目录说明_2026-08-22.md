# 文档整理与生成目录说明

更新时间：2026-08-22

## 1. 运行目录的处理结论

这些目录都在 `.gitignore` 中，不属于源码或正式实验归档，但用途不同：

| 目录 | 内容 | 删除影响 | 当前处理 |
| --- | --- | --- | --- |
| `.ros/` | ROS 运行状态、RTAB-Map 数据库 | 会丢失本地数据库；复用地图/定位时会受影响；`reset_db=true` 在线新实验通常从空库开始 | 已恢复并保留 |
| `build/` | colcon/CMake 编译中间文件 | 不影响源码和结果；删除后必须重新编译 | 已从回收站恢复并保留；需要清理时可重建 |
| `install/` | colcon 生成的安装空间 | 不影响源码和结果；删除后启动前必须重新构建 | 已从回收站恢复并保留；需要清理时可重建 |
| `log/` | colcon 和 ROS 构建日志 | 只影响查看旧构建日志 | 未恢复；可按需清理 |
| `.gazebo/` | Gazebo GUI/运行缓存 | 通常只丢失 GUI 状态和缓存，不影响世界文件 | 已恢复并保留 |
| `.config/` | Qt/Gazebo/RViz 本地界面配置 | 可能丢失本机 GUI 偏好 | 已恢复并保留 |
| `.rviz2/` | RViz2 持久化界面状态 | 可能丢失窗口布局或显示状态 | 已恢复并保留 |

结论：`.ros`、`.gazebo`、`.config`、`.rviz2` 不应在没有确认用途时直接永久删除；
本次已经恢复。`build` 和 `install` 虽然可以安全重建，但当前已恢复以保证容器启动后
能够直接使用现有安装空间；如果主动删除，不能直接启动导航，必须先运行
`colcon build --symlink-install`。`log` 可以清理，不影响实验本身。

实验结果、世界文件、参数快照和源码不依赖回收站中的这些目录。正式结果仍在根目录
`results/`，并由 Git 跟踪。
