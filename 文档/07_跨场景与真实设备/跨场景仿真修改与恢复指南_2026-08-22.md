# 跨场景仿真修改与恢复指南

版本日期：2026-08-22
当前冻结 profile：`adaptive_goal_line_045`
当前冻结代码基线：`de4ac49`
当前适用世界：`obstacle_course_large` / `indoor_obstacle_course_large.world`

本文说明如何在不破坏当前五点闭环基线的前提下改变仿真场景、保存实验、恢复旧场景，以及如何判断一次跨场景实验是否仍然验证了“在线 RGB-D 建图 + 实时目标导航”。

## 1. 当前基线不变的含义

当前算法每一段都重新接收一个 `NavigateToPose` 目标。规划器使用当时的机器人位姿、目标位姿和在线代价地图计算路径；不会读取历史轨迹，也不会使用固定世界坐标走廊。`line_bias` 只把本次起点到本次目标的直线作为软偏好，障碍物、footprint、膨胀层和碰撞监视器仍然是硬安全约束。

因此，改变以下内容不会改变算法本身：

| 可以改变的内容 | 影响 |
| --- | --- |
| 起点 `x_pose/y_pose` | 只改变 Gazebo 出生位置；需要同步回归脚本的 `--start-x/--start-y` |
| 目标坐标和目标顺序 | 改变每一段的实时规划问题，不是回放旧路线 |
| `--label` | 只改变结果目录，必须每次使用新名称 |
| `gazebo_gui`、`rviz`、`rtabmap_viz` | 只改变显示，不改变导航计算 |
| `settle_seconds` | 只改变发送目标前的等待时间，不改变规划参数 |

以下内容会改变算法或实验条件，必须新建 profile、分支或至少保存完整快照：

- `nav2_rgbd_params.yaml`、`collision_monitor_rgbd_params.yaml`；
- `demo.launch.py` 中的 profile、传感器、TF、地图和 Nav2 启动方式；
- `GoalLineSmacPlanner` 的 C++ 源码、行为树或控制器源码；
- 机器人 footprint、速度、RPP lookahead、inflation、碰撞监视区；
- 世界文件中的障碍物尺寸、位置、墙体、通道宽度和遮挡关系。

## 2. 推荐的跨场景变量

每轮只改变一个主要因素，其他条件保持当前冻结值：

1. 起点位置；
2. 单个或多个目标位置；
3. 障碍物数量；
4. 障碍物位置；
5. 通道宽度；
6. 障碍物高度、深度相机遮挡和视野可见性。

建议先做“只换目标顺序”，再做“只移动障碍物”，最后做通道宽度和遮挡压力测试。这样失败时可以判断是目标序列变化、环境几何变化，还是感知条件变化导致的。

## 3. 保存一个新场景

不要直接覆盖 `indoor_obstacle_course_large.world`。先创建实验分支，并复制世界文件：

```bash
cd /home/w417/RTAB-Map
git switch -c experiment/cross-scene-2026-08-22
cp src/rtabmap_tb3_nav/worlds/indoor_obstacle_course_large.world \
   src/rtabmap_tb3_nav/worlds/indoor_obstacle_course_cross_scene_01.world
```

编辑副本时，一次只改变明确的障碍物或通道。当前 `demo.launch.py` 的 `world` 参数是已注册名称，不是任意文件路径；新世界需要在其中增加一个明确的名称映射后才能通过 `world:=...` 启动。不要只把文件复制到 `worlds/` 后假定 launch 会自动发现它。

完成世界编辑后，先做静态检查：

```bash
git diff -- src/rtabmap_tb3_nav/worlds/indoor_obstacle_course_cross_scene_01.world
git diff --check
```

然后保存场景快照和当前算法参数：

```bash
mkdir -p results/跨场景_场景01_2026-08-22/参数快照
cp src/rtabmap_tb3_nav/worlds/indoor_obstacle_course_cross_scene_01.world \
   results/跨场景_场景01_2026-08-22/参数快照/世界文件.sdf
cp src/rtabmap_tb3_nav/config/nav2_rgbd_params.yaml \
   results/跨场景_场景01_2026-08-22/参数快照/Nav2参数.yaml
cp src/rtabmap_tb3_nav/config/collision_monitor_rgbd_params.yaml \
   results/跨场景_场景01_2026-08-22/参数快照/碰撞监视参数.yaml
git add src/rtabmap_tb3_nav/worlds/indoor_obstacle_course_cross_scene_01.world
git commit -m "experiment: add cross-scene world 01"
```

实验目录必须使用新的唯一前缀，例如 `自适应目标线_场景01_顺序A_2026-08-22/run_01`。脚本不会覆盖旧目录中的同名文件，但唯一名称是实验管理的必要条件。

## 4. 改参数后的重建规则

只改世界文件，通常不需要重新编译；重启 Gazebo、RTAB-Map 和 Nav2 即可。改 YAML、Python launch、Python 记录脚本或 C++ planner 后，执行：

```bash
cd /home/w417/RTAB-Map
sg docker -c './scripts/stop.sh'
sg docker -c './scripts/start.sh'
sg docker -c 'docker compose exec -T ros2 bash -lc \
  "source /opt/ros/humble/setup.bash && \
   cd /workspaces/rtabmap_tb3_nav && \
   colcon build --symlink-install"'
```

编译完成后，每次实验都用新容器状态启动。在线建图实验必须使用：

```bash
sg docker -c './scripts/launch_demo.sh \
  world:=obstacle_course_large \
  x_pose:=-8.5 y_pose:=0.0 \
  gazebo_gui:=false rviz:=false rtabmap_viz:=false \
  online:=true localization:=false reset_db:=true \
  navigation_profile:=adaptive_goal_line_045'
```

`reset_db:=true` 保证新实验从空的 RTAB-Map 数据库开始；这不会清除 Git 中保存的代码、世界文件或结果目录。改变世界后不能直接沿用旧地图结果作为新场景证据。

## 5. 如何恢复当前冻结基线

恢复时先查看目标文件和提交，不要用宽范围的 destructive 命令：

```bash

git log --oneline --decorate -5
git show --stat de4ac49
```

如果只需要恢复某个明确文件到冻结提交，可以使用：

```bash

  src/rtabmap_tb3_nav/launch/demo.launch.py \
  src/rtabmap_tb3_nav/config/nav2_rgbd_params.yaml
```

恢复后检查差异并重新编译：

```bash

sg docker -c './scripts/start.sh'

  "source /opt/ros/humble/setup.bash && \
   cd /workspaces/rtabmap_tb3_nav && \
   colcon build --symlink-install"'
```

如果要完整复现已归档的五点闭环，使用结果目录中保存的 `世界文件.sdf`、`导航参数.yaml`、`碰撞监视参数.yaml` 和 `实验参数.yaml`，并优先在冻结提交 `de4ac49` 上复现。旧结果不会被新实验覆盖。

## 6. 新场景的验收规则

每个场景、每个顺序至少独立重启三次。每次必须保存：

- 左侧 Gazebo 真值俯视图和右侧 RViz 风格地图/代价地图的 `trajectory_comparison.png`；
- 在线地图轨迹、Gazebo 真值轨迹和每段 CSV；
- Nav2、碰撞监视器、世界文件和实验参数快照；
- 每段状态、墙钟耗时、仿真耗时、轨迹长度和末端 XY 误差；
- Gazebo contacts 总数、过滤地面后的非地面接触对。

正式成功条件是所有目标段 `status=4`、非地面 contacts 为 0，且结果目录具有完整轨迹和参数证据。三次都通过后，才把该场景列为“当前 profile 在该场景通过”；不能将单一场景结果表述为对任意未知环境的保证。

## 7. 当前实验归档约定

本轮新顺序使用以下目录，三次运行互不覆盖：

```text
results/04_自适应目标线多目标/自适应目标线_顺序实验1_CADBMC_2026-08-22/run_01..run_03
results/04_自适应目标线多目标/自适应目标线_顺序实验2_BMACDB_2026-08-22/run_01..run_03
```

实验 1 为 `C -> A -> D -> B -> M -> C`，实验 2 为 `B -> M -> A -> C -> D -> B`。两组都在同一在线 RGB-D 场景中改变起点和目标顺序，不使用固定路线；最终统一分析时与原始 `M -> A -> B -> C -> D -> M` 三次结果比较。
