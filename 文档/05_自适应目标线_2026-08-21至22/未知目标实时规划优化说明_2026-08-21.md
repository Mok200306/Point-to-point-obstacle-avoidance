# 未知目标实时规划优化说明

更新时间：2026-08-21

## 结论

本轮修正针对的问题是：把目标从旧的 (8.5, 0.0) 改成 (5.0, -3.0) 后，机器人仍然先沿着旧 large 场景路线行驶，并在旧障碍前停止。

根因不是 Nav2 把旧轨迹保存成了离散航点，而是旧 profile fast_goalline_045_v4 在自定义 GoalLineSmacPlanner 中启用了当前 large 场景的固定 world_x/world_y 分段侧向代价。它是“每次 A* 规划时重新搜索、但带固定场景软偏好”，不是控制指令回放；不过对换目标的实验来说，这个先验仍然会把规划拉向旧路线。

本轮新增并设为默认的 adaptive_goal_line_045：

- 关闭 side_bias_enabled；
- 关闭 side_bias_target_world_y_enabled；
- 关闭 side_bias_target_schedule_enabled；
- 每次 createPlan(start, goal) 从当前起点和当前目标重新计算直线偏差；
- 保留实时 /nav_map、RGB-D obstacle layer、inflation、Smac A*、RPP 和 collision monitor；
- 不发送中间航点，不播放历史轨迹，不使用 large 场景固定 x/y 走廊。

因此，当前默认 profile 才是用于新起点、新终点和后续新场景测试的配置。v4 仍保留为当前 large 场景的冻结 benchmark，不再作为通用目标 profile。

## 当前规划链路

    Gazebo RGB-D 深度
        -> /camera/points
        -> point_cloud_xyz
        -> /camera/obstacles + /camera/cloud
        -> RTAB-Map online 更新 /map 和 map->odom
        -> map_padder 生成固定尺寸 /nav_map
        -> global costmap: StaticLayer + RGB-D obstacle layer + inflation
        -> GoalLineSmacPlanner: 当前 start/goal + 实时 costmap 的 Smac A*
        -> /plan 和 /received_global_plan
        -> RPP 前视跟踪 /local_plan
        -> velocity_smoother
        -> collision_monitor /cmd_vel_safe
        -> Gazebo TurtleBot3

其中：

1. RTAB-Map 负责在线视觉/深度建图和 map -> odom 位姿估计，不负责决定绕行方向。
2. global costmap 把已经观察到的墙、栏杆和 RGB-D 障碍转换成规划栅格；inflation 产生障碍物外侧的软代价，footprint 和 lethal cell 仍是硬可行性约束。
3. GoalLineSmacPlanner 继承 Nav2 SmacPlanner2D。它仍然对每个 NavigateToPose 目标和每次需要重规划的请求运行 A*，并且临时修改非 lethal 栅格后恢复原 costmap。
4. RPP 不搜索拓扑路线，而是沿 /plan 的前视点连续跟踪，根据曲率、代价和前向碰撞预测调速；它负责平顺转弯，不负责替代全局规划器。
5. collision monitor 是最后的安全过滤层。触发 slowdown/stop 时机器人可能减速或停下，这是安全行为，不代表它找到了新路线。

## 自适应目标线的代价含义

当前 profile 的关键覆盖参数为：

| 参数 | 值 | 作用 |
| --- | ---: | --- |
| inflation_radius | 0.45 m | 障碍物外侧软安全梯度；不改变车体 footprint |
| cost_scaling_factor | 4.5 | adaptive profile 的 global/local inflation 衰减速度 |
| cost_travel_multiplier | 6.0 | Smac 累计 costmap 代价的权重 |
| line_bias_enabled | true | 使路径倾向当前起点到当前终点直线 |
| line_bias_max_cost | 60.0 | 直线偏差软代价上限 |
| line_bias_distance_scale | 2.0 m | 偏离直线的尺度 |
| line_bias_exponent | 2.0 | 二次偏差惩罚，形成平滑的目标方向偏好 |
| side_bias_enabled | false | 禁用固定左右绕行方向 |
| side_bias_target_schedule_enabled | false | 禁用固定 large 场景分段走廊 |
| RPP desired_linear_vel | 0.28 m/s | 直线段目标速度 |
| RPP lookahead | 0.62--1.20 m | 提前看到弯道，减少贴着障碍角点才转向 |

对已知、非 lethal 栅格，规划器的直线偏差可以近似理解为：

    line_cost = min(60 * (distance_to_current_start_goal_line / 2.0)^2, 252)
    cell_cost = max(original_costmap_cost, line_cost)

这只是软偏好。直线被障碍物阻断时，A* 必须绕行；绕开后，离当前目标线较近的可行栅格通常更便宜。它不是“直线一定最高分”，也不能穿过 lethal cell。

## RViz 中两条线的含义

RViz 已配置以下显示：

- /plan：Nav2 当前的实时全局规划路径，是机器人真正要跟踪的全局路线；
- /received_global_plan：controller 收到的全局路径；
- /local_plan：RPP 当前局部控制路径；
- /goal_line：黑色起点到目标参考线，仅用于对比，不参与规划、不发布速度。

goal_line_visualizer.py 订阅 /goal_line_request 和 RViz 的 /goal_pose，在收到新目标时从当前 TF 位姿取起点，再发布黑色线。第二段任务开始时，起点是第一段实际结束位姿，不是旧实验的初始点。

## 本轮实验结论

连续任务为：

    起点 (-8.5, 0.0) -> A (5.0, -3.0) -> B (5.0, 6.0)

实验使用 adaptive_goal_line_045、online RGB-D SLAM、reset_db=true 和同一场景内连续两次 NavigateToPose。两段均从当前实时位姿重新规划，Nav2 均返回 status=4。

| 阶段 | 目标 | 状态 | wall 时间 | map 轨迹长度 | 末端 XY 误差 |
| --- | --- | ---: | ---: | ---: | ---: |
| 起点到 A | (5.0, -3.0) | 4 | 76.711 s | 15.230 m | 0.108 m |
| A 到 B | (5.0, 6.0) | 4 | 60.227 s | 10.456 m | 0.146 m |
| 合计 | 两段 | 4/4 | 136.938 s | 25.686 m | 分段统计 |

Gazebo contacts 共记录 325050 条 contact 消息；过滤 ground_plane 后，机器人与墙、栏杆、箱体和柱体的非地面接触为 (none)。这是本次物理无碰撞证据。结果目录和双视图见 自适应目标线多目标实验记录_2026-08-21.md。

## 当前边界

本轮证明的是“改变目标后不再执行旧的固定大场景走廊，并可在当前场景完成连续双目标任务”。它还不是任意未知房间的完整泛化证明：相机视野之外的障碍尚未进入 costmap，RTAB-Map 也没有自动 frontier exploration；深度漏检、窄通道和错误 TF 仍可能导致停下或失败。

下一步应保持本 profile 不变，测试不同起点、不同目标、不同障碍布局各至少三次，并把成功率、耗时、路径长度、末端误差和物理 contacts 分开记录。只有跨场景稳定后，才把它写成通用 RGB-D 导航方法，而不是当前场景的验证结果。
