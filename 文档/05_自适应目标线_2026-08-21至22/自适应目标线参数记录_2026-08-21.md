# 自适应目标线参数记录

更新时间：2026-08-21
适用 profile：adaptive_goal_line_045
代码入口：src/rtabmap_tb3_nav/launch/demo.launch.py
基础参数：src/rtabmap_tb3_nav/config/nav2_rgbd_params.yaml

## 设计目标

本 profile 用于新起点、新终点和后续跨场景验证。它不包含当前 large 场景的固定左右绕行 schedule；规划器只根据当前 NavigateToPose 的 start、goal 和实时 costmap 做搜索。

nav2_rgbd_params.yaml 为兼容历史 profile 仍保留 side_bias_* 参数，但 demo.launch.py 在 adaptive_goal_line_045 中明确覆盖为：

    line_bias_enabled: true
    side_bias_enabled: false
    side_bias_apply_to_unknown: false
    side_bias_target_world_y_enabled: false
    side_bias_target_schedule_enabled: false

## 起点和终点怎么改

只修改起点/终点数字不需要重新编译：

    # Gazebo 出生点
    sg docker -c './scripts/launch_demo.sh world:=obstacle_course_large x_pose:=-8.5 y_pose:=0.0 gazebo_gui:=true rviz:=true rtabmap_viz:=false online:=true localization:=false reset_db:=true navigation_profile:=adaptive_goal_line_045'

    # map 坐标系目标
    sg docker -c 'docker compose exec -T ros2 bash -lc "source /opt/ros/humble/setup.bash && source /workspaces/rtabmap_tb3_nav/install/setup.bash && ros2 run rtabmap_tb3_nav send_goal.py --x 5.0 --y -3.0 --yaw 0.0 --settle-seconds 5"'

注意：x_pose/y_pose 是 Gazebo world 坐标；send_goal.py --x/--y 默认是 RViz 的 map 坐标。当前 large world 中两者近似对齐，换场景后应以 RViz 的 map 坐标为准。

两段任务使用：

    sg docker -c './scripts/multi_goal_regression.sh --goal-a-x 5.0 --goal-a-y -3.0 --goal-b-x 5.0 --goal-b-y 6.0 --label "自适应目标线_多目标_新实验_2026-08-21" --profile adaptive_goal_line_045 --settle-seconds 5'

## 修改后要不要 build

| 修改内容 | 是否需要 colcon build | 是否需要重建 Docker 镜像 |
| --- | --- | --- |
| --x/--y/--yaw、x_pose/y_pose、world 参数 | 否 | 否 |
| Python 脚本、launch、C++ planner、YAML | 是 | 通常否；使用挂载工作区即可 |
| Dockerfile、底盘模型补丁、系统依赖 | 是 | 是，执行 scripts/build.sh |

代码或 YAML 修改后：

    cd /home/w417/RTAB-Map
    sg docker -c 'docker compose exec -T ros2 bash -lc "source /opt/ros/humble/setup.bash && cd /workspaces/rtabmap_tb3_nav && colcon build --symlink-install"'

然后停止旧 launch，再以新的 profile 启动。只改目标时，直接重新启动仿真并发送新目标即可。

## 复现和结果保存规则

每次实验使用唯一 --label。同名 label 会覆盖同一结果目录中的 PNG、CSV、YAML 和世界快照；新实验应使用 _run_01、_run_02 等后缀。正式归档的 v4 三次结果位于 results/03_V4快速目标线/optimization_2026-08-21/，本轮修正版位于 results/04_自适应目标线多目标/自适应目标线_多目标_修正版_2026-08-21/。

结果至少应保存：

- trajectory_comparison.png：左 Gazebo 俯视真值、右 RViz 风格地图；
- trajectory.csv 或分段 CSV；
- metrics.yaml：状态、wall/sim 时间、路径长度、末端误差；
- 导航参数、碰撞监视参数和世界文件快照；
- 物理 contacts 过滤结果。

## 当前冻结和下一步

当前冻结的是“参数可复现的自适应首轮 profile”，不是“所有场景都已验收”。后续测试应保持这组参数不变，至少覆盖：

1. 起点不在 (-8.5,0.0) 的任务；
2. 目标不在当前 A/B 位置的任务；
3. 障碍栏位置、方向或间距变化的场景；
4. 每种设置至少三次成功率和无碰撞统计。

真实 D435i 进入条件和硬件迁移步骤见 V4_REPRODUCTION_AND_CROSS_SCENE_VALIDATION_2026-08-21.md。在完成不同障碍布局的仿真回归前，不把当前结果写成真实环境或任意未知环境保证。
