## 2. 设计目标

场景 01 主要验证障碍物平移和旋转后的泛化能力。场景 02 进一步改变通道的拓扑：
三道主障碍交错布置，使起点到终点的直线被多次阻断，机器人需要先向北侧绕行，
通过中央区域后再向南侧回收，形成可观察的交错走廊。

保持不变的条件：

- 房间边界仍约为 `20.2 m x 14.2 m`，墙体中心仍在 `x=+-10`、`y=+-7`；
- 起点 marker 仍为 `(-8.5, 0.0)`，终点 marker 仍为 `(8.5, 0.0)`；
- TurtleBot3 Waffle、RGB-D 传感器、RTAB-Map 在线建图和 Nav2 启动链路不变；
- `adaptive_goal_line_045`、footprint、膨胀层和 collision monitor 不因换场景而改变；
- 不加入动态障碍物，也不把 Gazebo 世界文件作为规划先验地图。

## 3. 内部布局

三道主障碍保留场景 01 的模型尺寸，只调整位置和方向：

| 模型 | 中心位姿 `(x, y, z, yaw)` | 尺寸 `(x, y, z)` | 作用 |
| --- | --- | --- | --- |
| `barrier_west` | `(-5.2, 0.0, 0.45, 0)` | `0.55 x 4.4 x 0.9` | 阻断西侧中线，要求从北侧绕过 |
| `barrier_center` | `(0.0, -1.7, 0.45, 1.5708)` | `5.6 x 0.55 x 0.9` | 旋转为纵向，保持北侧过渡路线可用 |
| `barrier_east` | `(5.2, 1.8, 0.45, 0)` | `0.55 x 4.0 x 0.9` | 阻断东侧中线，要求在东侧向南回收 |

其余箱体和柱体分布在上下侧区域，增加环境复杂度但不封死中间通道：

- 西侧箱体：`(-7.1, 4.5)`、`(-7.0, -4.2)`；
- 中部箱体：`(-2.8, 4.6)`、`(0.0, -5.0)`；
- 东侧箱体：`(7.1, 5.0)`、`(7.1, -4.5)`；
- 中部柱体：`(2.7, 4.25)`、`(-2.7, -4.25)`。

这些位置是场景 02 的环境定义，不是机器人要依次访问的 waypoint，也不是规划器
内部的固定路线。

## 5. 静态检查结果

已对新 SDF 做 XML 和几何检查：

- world name：`indoor_obstacle_course_cross_scene_02`；
- 模型数量：18，模型名称全部唯一；
- 当前世界文件不包含 `<state>` 块，也不包含内嵌 `waffle`；机器人只由启动脚本生成；
- 起点到终点的 `y=0` 直线被 `barrier_west`、`barrier_center` 和 `barrier_east`
  三处阻断；
- 以 `0.45 m` 的中心安全半径做二维栅格检查，存在连续通路，近似最短长度约
  `19.82 m`；以更保守的 `0.75 m` 检查仍存在通路，近似长度约 `20.49 m`；
- 上述栅格结果只是环境设计的可行性筛查，不等于 Nav2 已成功，也不替代后续
  Gazebo 物理 contacts 和多次导航验收。

规范化后的启动日志显示 `spawn_turtlebot3.launch.py` 成功生成唯一的 `waffle`，
不再出现 `Entity [waffle] already exists`。规范化只改变世界文件的表达方式和顶层
位姿来源，没有移动用户确认的障碍物几何。

```bash

sg docker -c './scripts/start.sh'
sg docker -c 'docker compose exec -T ros2 bash -lc "source /opt/ros/humble/setup.bash && cd /workspaces/rtabmap_tb3_nav && colcon build --symlink-install"'
```

只启动 Gazebo、RViz2、RTAB-Map 和在线建图，不发送目标：

```bash
sg docker -c './scripts/launch_demo.sh \
  world:=obstacle_course_large \
  world_file:=indoor_obstacle_course_cross_scene_02.world \
  x_pose:=-8.5 y_pose:=0.0 \
  gazebo_gui:=true rviz:=true rtabmap_viz:=false \
```

3. 中间是否保留连续的上绕行、中央过渡、下回收空间；
4. RViz2 中是否正常出现 TF、RGB-D 点云、在线地图和 costmap。
