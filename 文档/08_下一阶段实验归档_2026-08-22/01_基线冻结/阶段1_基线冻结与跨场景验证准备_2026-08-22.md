## 2. 当前冻结内容

### 2.1 运行模式

~~~text
Gazebo RGB-D
  -> RTAB-Map online SLAM
  -> /map 和 map->odom
  -> /nav_map + Nav2 global/local costmap
  -> GoalLineSmacPlanner / SmacPlanner2D
  -> RPP
  -> collision_monitor
  -> TurtleBot3 Waffle
~~~

当前启动约束：

- online=true；
- localization=false；
- reset_db=true，每次从新的在线数据库开始；
- 不使用 /scan，障碍物来自 RGB-D 深度点云；
- 每一个目标都会创建新的 NavigateToPose action；
- line_bias 只对当前起点到当前目标的直线施加软偏好；
- 已关闭 large 场景固定世界坐标走廊和目标点调度。

因此当前 profile 不是预存路线回放。黑色起终点连线是记录用参考线，不是控制器
接收的固定轨迹。固定尺寸的 /nav_map 只是为了避免地图尺寸变化造成 costmap
反复 resize，也不是固定路线地图。

### 2.2 关键参数

| 模块 | 冻结值 |
| --- | --- |
| 全局规划器 | GoalLineSmacPlanner，底层 SmacPlanner2D |
| inflation_radius | 0.45 m |
| 机器人 footprint | 0.60 x 0.48 m，padding 0.03 m |
| RPP 目标速度 | 0.28 m/s |
| RPP 前视距离 | 0.62--1.20 m，默认 0.80 m |
| 全局代价 cost_travel_multiplier | 6.0 |
| 目标 XY 容差 | 0.12 m |
| 目标 yaw 容差 | 0.15 rad |
| collision monitor | /cmd_vel -> /cmd_vel_safe |

## 5. 阶段 2 的准备方案

### 5.1 需要增加的实验基础设施

当前 demo.launch.py 直接识别 obstacle_course 和 obstacle_course_large；为了加载多个
自定义世界，下一阶段需要增加通用的 world_file:=... 或受控场景名称映射。这只是
场景加载和实验记录能力，不改变规划算法本身。

多目标回归脚本已经支持 --world-file 和 --contacts-topic，因此每个新场景可以使用
独立世界文件、Gazebo contacts 主题和结果标签，详见
[multi_waypoint_regression.sh](../../../scripts/multi_waypoint_regression.sh)。

### 5.2 建议的三个场景

1. 只平移或旋转现有障碍物，检查是否依赖旧障碍物坐标；
2. 改变障碍物排列方向，形成不同的绕行方向；
3. 增加窄通道和非对称障碍，测试提前绕行、局部控制和安全停止。

每个场景至少运行三次，保持 adaptive_goal_line_045、RGB-D 配置和机器人 footprint
不变。目标点应使用新的坐标，且在实验前只用 Gazebo 几何确认存在可行路线，不能把
该几何地图提供给 Nav2。

### 5.3 阶段 2 验收条件

- 每个场景至少 3/3 完整 run 成功；
- 每个目标段均返回 status=4；
- 过滤地面后非地面 contacts 为 0；
- 保存三次轨迹图、CSV、metrics、参数快照、世界文件和 contacts；
- 记录 wall 时间、轨迹长度、末端误差和最小障碍距离；
- 失败时先分类为地图、TF、全局规划、局部跟踪或安全层问题，不直接盲目改参数。
