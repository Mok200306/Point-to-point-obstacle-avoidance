# 场景 02 恢复增强 v5 参数冻结与复现手册

日期：2026-08-23
profile：`adaptive_goal_line_050_recovery_v5`
适用场景：`indoor_obstacle_course_cross_scene_02.world`
冻结性质：场景 02 验收 profile，**不覆盖默认 `adaptive_goal_line_045`**

## 1. 保持不变的部分

- Ubuntu 20.04 主机 Docker；容器 Ubuntu 22.04 + ROS 2 Humble；
- TurtleBot3 Waffle 仿真底盘和 RGB-D 相机；不使用 `/scan`；
- RTAB-Map 在线 RGB-D SLAM，`online:=true`、`localization:=false`；
- Nav2 实时 global/local costmap、Smac 系列全局规划和 RPP 局部控制；
- 场景 02 世界文件和用户确认的障碍物坐标、尺寸、方向；
- 机器人初始位姿 `M=(-8.5,0.0)`；
- 目标顺序由脚本实时逐段发送，不是预先录制的路线。

## 2. v5 运行时参数

### 全局规划器

| 参数 | v5 值 | 作用 |
|---|---:|---|
| 插件 | `rtabmap_tb3_nav/GoalLineSmacPlanner` | Smac 栅格规划 + 当前起点到目标线软偏好 |
| `line_bias_enabled` | `true` | 让可行路径倾向当前目标方向 |
| `line_bias_max_cost` | `60.0` | 目标线偏离代价上限 |
| `line_bias_distance_scale` | `2.0` | 偏离目标线的软代价尺度 |
| `line_bias_exponent` | `2.0` | 偏离距离二次惩罚 |
| `side_bias_enabled` | `false` | 关闭场景专用固定侧向走廊 |
| `side_bias_target_schedule_enabled` | `false` | 不使用固定世界坐标分段路径 |
| `cost_travel_multiplier` | `6.0` | 提高累计 cost 对路径选择的影响 |
| `max_planning_time` | `1.0 s` | 单次规划时间上限（基础 YAML） |

### RPP 局部控制器

| 参数 | v5 值 |
|---|---:|
| `desired_linear_vel` | `0.28 m/s` |
| `lookahead_dist` | `0.68 m` |
| `min_lookahead_dist` / `max_lookahead_dist` | `0.52 / 1.05 m` |
| `lookahead_time` | `1.5 s` |
| `use_rotate_to_heading` | `true` |
| `allow_reversing` | `false` |
| `cost_scaling_dist` | `0.65 m` |
| `regulated_linear_scaling_min_radius` | `0.80 m` |
| `max_allowed_time_to_collision_up_to_carrot` | `1.5 s` |
| `inflation_cost_scaling_factor` | `4.5` |

### Costmap 与恢复

- global/local `inflation_radius=0.50 m`；这是 v5 相比原参数 `0.45 m` 增加的安全 margin，不是实体障碍物；
- global/local inflation `cost_scaling_factor=4.5`；
- progress checker `movement_time_allowance=30 s`；
- 恢复行为树：路径每 `2 Hz` 检查，路径有效时约 `20 s` 过期重算；恢复顺序包括清理 local/global costmap、`Spin 1.57 rad`、`BackUp 0.60 m @ 0.12 m/s` 和 `Wait 2 s`，最多 8 次恢复循环；
- collision monitor 保持独立的前方 slowdown/stop 硬安全层，没有因为追求成功而关闭。

## 3. 复现步骤

```bash
cd /home/w417/RTAB-Map
sg docker -c './scripts/stop.sh'
sg docker -c './scripts/start.sh'
sg docker -c 'docker compose exec -T ros2 bash -lc "source /opt/ros/humble/setup.bash && cd /workspaces/rtabmap_tb3_nav && colcon build --symlink-install"'
```

终端 1：

```bash
sg docker -c './scripts/launch_demo.sh gazebo_gui:=true rviz:=true rtabmap_viz:=false reset_db:=true online:=true localization:=false world_file:=/workspaces/rtabmap_tb3_nav/src/rtabmap_tb3_nav/worlds/indoor_obstacle_course_cross_scene_02.world navigation_profile:=adaptive_goal_line_050_recovery_v5 x_pose:=-8.5 y_pose:=0.0'
```

终端 2：

```bash
sg docker -c './scripts/multi_waypoint_regression.sh \
  --start-name M --start-x -8.5 --start-y 0.0 \
  --goal N:8.5:0.0:0.0 --goal X:-3.0:-4.0:0.0 \
  --goal Y:5.0:5.0:0.0 --goal M:-8.5:0.0:0.0 \
  --label 05_跨场景验证/场景02/复现_四点闭环v5_$(date +%Y%m%d_%H%M%S) \
  --profile adaptive_goal_line_050_recovery_v5 \
  --world-file src/rtabmap_tb3_nav/worlds/indoor_obstacle_course_cross_scene_02.world'
```

不要复用正式 `run_01`、`run_02`、`run_03` 标签。脚本会自动保存 `metrics.yaml`、`实验参数.yaml`、四段轨迹、双视角图、世界和参数快照。复现结束后检查：

```bash
rg -n 'overall_succeeded|nav2_status|gazebo_non_ground_contact|gazebo_contact_pairs' results/05_跨场景验证/场景02/复现_四点闭环v5_*/metrics.yaml
```

## 4. 回退到原参数

若要复现本轮 M→N 原参数基线，仍显式使用：

```text
navigation_profile:=adaptive_goal_line_045
```

不要修改 `nav2_rgbd_params.yaml` 来回切换；profile 是 launch 运行时覆盖，历史实验目录内已有基础 YAML 快照和运行条件。
