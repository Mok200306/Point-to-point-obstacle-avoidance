# 阶段 2：跨场景场景 01 复现参数与命令

日期：2026-08-22

本文件冻结本轮 9 次实验的运行条件。不要用它覆盖历史 v4；它是
`adaptive_goal_line_045` 在 `cross_scene_01` 上的独立场景快照。

## 1. 固定输入

| 项目 | 值 |
| --- | --- |
| 主机 | Ubuntu 20.04、RTX 4090 |
| 容器 | Ubuntu 22.04、ROS 2 Humble、Gazebo、RViz2 |
| 世界文件 | `src/rtabmap_tb3_nav/worlds/indoor_obstacle_course_cross_scene_01.world` |
| Gazebo 分支参数 | `world:=obstacle_course_large` |
| profile | `adaptive_goal_line_045` |
| 建图 | `online:=true` |
| 定位模式 | `localization:=false` |
| 数据库 | `reset_db:=true`，每次 run 独立在线建图 |

| 膨胀代价缩放 | profile 运行时全局/局部均为 `4.5` |
| RPP 期望线速度 | `0.28 m/s` |

| 固定场景走廊 | 关闭：`side_bias_enabled=false`，目标 y/schedule 均关闭 |
| 机器人 footprint | `0.60 x 0.48 m`，`footprint_padding=0.03 m` |

## 2. 点位定义

```text
M = (-8.5,  0.0), yaw=3.1415926
A = ( 5.0, -3.0), yaw=0.0
B = ( 5.0,  6.0), yaw=0.0
C = (-5.0,  4.0), yaw=3.1415926
D = ( 0.0,  0.0), yaw=0.0
```

实际顺序：

```text
原始闭环：M -> A -> B -> C -> D -> M
顺序实验1：C -> A -> D -> B -> M -> C
顺序实验2：B -> M -> A -> C -> D -> B
```

## 4. 每次 run 的启动规则

先在一个终端启动 Gazebo、RViz2、RTAB-Map 和 Nav2。命令保持运行，直到对应的
`multi_waypoint_regression.sh` 完成；完成后按 `Ctrl+C` 停止，再启动下一次 run。

### 从 M 点开始

```bash
sg docker -c './scripts/launch_demo.sh \
  world:=obstacle_course_large \
  world_file:=indoor_obstacle_course_cross_scene_01.world \
  x_pose:=-8.5 y_pose:=0.0 \
  gazebo_gui:=true rviz:=true rtabmap_viz:=false \
  online:=true localization:=false reset_db:=true \
  navigation_profile:=adaptive_goal_line_045'
```

### 从 C 点开始

只把出生位姿改为：

```bash
x_pose:=-5.0 y_pose:=4.0
```

### 从 B 点开始

只把出生位姿改为：

```bash
x_pose:=5.0 y_pose:=6.0
```

不要把旧的 v4 profile 用在这组场景验收中；v4 的坐标走廊是 large 场景历史基准，
本场景验收必须显式使用 `adaptive_goal_line_045`。

## 5. 正式回归命令

脚本自动从 SDF world name 生成 contacts 主题，自动保存结果目录，不需要手动指定
`--contacts-topic`。以下 label 已与本轮结果对应；再次运行时应使用新的日期或
`rerun_01` 子目录，避免覆盖正式证据。

### 原始闭环 MABCDM

```bash
sg docker -c './scripts/multi_waypoint_regression.sh \
  --goal A:5.0:-3.0:0.0 \
  --goal B:5.0:6.0:0.0 \
  --goal C:-5.0:4.0:3.1415926 \
  --goal D:0.0:0.0:0.0 \
  --goal M:-8.5:0.0:3.1415926 \
  --start-name M --start-x -8.5 --start-y 0.0 \
  --world-file src/rtabmap_tb3_nav/worlds/indoor_obstacle_course_cross_scene_01.world \
  --label "05_跨场景验证/场景01/跨场景场景01_五点闭环_MABCDM_2026-08-22/run_01" \
  --profile adaptive_goal_line_045 --settle-seconds 5'
```

把 label 中的 `run_01` 改成 `run_02`、`run_03` 即可复现同组其他 run。

## 7. 手动调整场景后的恢复规则

- 只移动障碍物：保留当前参数和 profile，复制一个新的 world 文件名，并使用新的
  结果 label；不要覆盖本轮 `世界文件.sdf` 快照。
- 改出生点：只改 `x_pose`、`y_pose` 和回归脚本的 `--start-*`，障碍物不动。
- 改导航参数：先复制对应结果目录中的 YAML 作为实验快照，改动后重新 build，使用
  新 profile 或新日期目录，不能把新结果写入本轮正式目录。
- 恢复本轮场景：使用仓库中的
  `src/rtabmap_tb3_nav/worlds/indoor_obstacle_course_cross_scene_01.world`，并恢复
  `adaptive_goal_line_045`、`online=true`、`reset_db=true`。

本轮逐 run 的参数和世界快照位于三个 `results/05_跨场景验证/场景01/跨场景场景01_*` 目录中；它们是比
主机当前工作区更直接的实验审计证据。
