# 阶段 2：跨场景场景 01 九次五点闭环实验总结

日期：2026-08-22

阶段状态：通过仿真验收

冻结 profile：`adaptive_goal_line_045`

## 1. 验收结论

在用户手动确认后的 `indoor_obstacle_course_cross_scene_01.world` 上，三种五点闭环
顺序各运行三次，共 9 次完整实验。9 次均完成全部 5 段导航，结果为：

- run 成功率：`9/9 = 100%`；
- 目标段成功率：`45/45 = 100%`，每段 Nav2 `status=4`；
- 非地面 Gazebo contacts：`0/9`；
- 每个 run 都有左右双视角 `trajectory_comparison.png`、分段轨迹 CSV、在线地图轨迹、
  Gazebo 真值轨迹、参数快照和世界快照。

这证明当前算法在这个障碍布局变化后的仿真场景中仍能在线 RGB-D 建图、按实时目标
顺序逐段规划和完成闭环。它不等价于“任意未知房间都保证成功”，真实 D435i 和真实
底盘仍未纳入本次结论。

## 2. 场景和机器人修正

本次使用的世界文件：

[`indoor_obstacle_course_cross_scene_01.world`](../../src/rtabmap_tb3_nav/worlds/indoor_obstacle_course_cross_scene_01.world)

处理原则是保留用户调整后的障碍物位置，只修正机器人出生和世界加载方式：

- 删除世界文件中保存的内嵌 `waffle`，避免启动文件再次 spawn 后出现两个机器人；
- 删除 Gazebo 保存状态块 `<state>`，避免状态块覆盖启动时的出生位姿；
- 将状态块中的障碍物位姿固化到顶层模型，障碍物几何和用户确认的位置不移动；
- 每次由 `demo.launch.py` 通过 `x_pose`、`y_pose` 生成唯一 TurtleBot3，yaw 由启动参数
  控制，默认是 0；
- `navigation_trial.py` 支持 Gazebo 保存格式中的 `<static>1</static>` 和 `<state>`，
  因而左右轨迹图能够读取同一份世界几何。

规划器没有读取 SDF 作为先验地图。SDF 只交给 Gazebo 进行物理仿真，交给绘图程序
显示障碍物，回归脚本从世界名生成 contacts 主题；Nav2 实际使用的是 RTAB-Map 和
RGB-D 障碍检测产生的在线地图与代价地图。

## 6. 结果解释和边界

当前 `adaptive_goal_line_045` 关闭了 v4 的场景坐标走廊：`side_bias_enabled=false`、
`side_bias_target_world_y_enabled=false`、`side_bias_target_schedule_enabled=false`，
只保留每次规划调用根据当前起点和目标重新计算的目标线软偏好。每一段目标改变后，
Nav2 收到新的 `NavigateToPose`，Smac 从实时 costmap 重新搜索，RPP 跟踪新路径。

本次结果支持以下表述：

- 在一个障碍物位置和方向已变化的场景中，算法没有复用 large 场景的固定走廊；
- 在仿真 RGB-D、在线 RTAB-Map 和静态障碍物条件下，五点闭环和两种反向顺序均通过；
- 物理 contacts 过滤后没有机器人与障碍物、墙体、箱体或柱体的接触对。

本次结果不支持以下更强表述：

- 任意未知房间、任意随机障碍物或动态行人都能 100% 成功；
- 轨迹一定是全局最短路径；
- 仿真 contacts=0 等于真实 D435i 和真实底盘已验证。

`minimum_approx_clearance_m` 是依据记录地图和几何的近似诊断值，部分段可能为负，
不能替代 Gazebo 接触证据或真实机器人安全距离。当前验收以 Nav2 全段成功和完整
contacts 过滤为硬条件。

停止 GUI 时偶尔出现 `map_padder.py rcl_shutdown already called` 或 RViz 退出码
`-11`，属于 Ctrl+C 的可视化/ROS 退出竞态；本轮正式 run 的 trial 均以退出码 0
完成，不能把 GUI 收尾信息计为导航失败。
