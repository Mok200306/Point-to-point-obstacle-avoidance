## 1. 本轮做了什么

场景 02 的障碍物布局保持不变，没有通过世界坐标 waypoint 或固定走廊引导机器人。v5 是针对前一轮偶发安全停止和恢复不足问题新增的通用恢复 profile：规划仍然来自当前起点、当前目标和实时 costmap；变化集中在恢复行为、提前碰撞预测、目标线软偏好和很小的 `0.50 m` inflation margin。

每个 run 都在一个持续的在线 RGB-D 会话中依次发送四个 `NavigateToPose` 目标。到达一个目标后才发送下一个目标，因此轨迹不是预先录制的闭环路线。

## 4. 验收结论

本轮可以正式记录为：**在场景 02 的静态障碍布局下，RGB-D 在线建图、实时 costmap、实时全局规划、RPP 局部跟踪和恢复行为共同完成了四点闭环导航，三次均成功且未发生非地面 Gazebo 物理接触。**

边界必须保留：

- v5 没有把场景 02 的障碍位置写进规划器，也没有回放任何历史轨迹；
- 结果证明的是当前仿真场景下的在线规划能力，不是对任意未知环境的成功率保证；
- `minimum_approx_clearance_m` 为简化几何估计，部分值为负，硬碰撞结论以 Gazebo contacts 为准；
- v5 是场景 02 的恢复增强候选，不替换默认 `adaptive_goal_line_045`，后续复现必须显式指定 profile。

## 5. 复现命令

先终端 1 启动独立场景：

```bash
cd /home/w417/RTAB-Map
sg docker -c './scripts/stop.sh'
sg docker -c './scripts/start.sh'
sg docker -c './scripts/launch_demo.sh gazebo_gui:=true rviz:=true rtabmap_viz:=false reset_db:=true online:=true localization:=false world_file:=/workspaces/rtabmap_tb3_nav/src/rtabmap_tb3_nav/worlds/indoor_obstacle_course_cross_scene_02.world navigation_profile:=adaptive_goal_line_050_recovery_v5 x_pose:=-8.5 y_pose:=0.0'
```

再终端 2 依次发送四个目标并保存新目录（不要使用已经存在的 `run_01..run_03`）：

```bash
cd /home/w417/RTAB-Map
sg docker -c './scripts/multi_waypoint_regression.sh \
  --start-name M --start-x -8.5 --start-y 0.0 \
  --goal N:8.5:0.0:0.0 \
  --goal X:-3.0:-4.0:0.0 \
  --goal Y:5.0:5.0:0.0 \
  --goal M:-8.5:0.0:0.0 \
  --label 05_跨场景验证/场景02/复现_四点闭环v5_$(date +%Y%m%d_%H%M%S) \
  --profile adaptive_goal_line_050_recovery_v5 \
  --world-file src/rtabmap_tb3_nav/worlds/indoor_obstacle_course_cross_scene_02.world \
  --settle-seconds 5'
```

正式实验的 run 目录不会被新实验覆盖；使用新的 `--label` 即可生成新的结果目录。
