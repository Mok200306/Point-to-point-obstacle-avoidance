# 项目交接总览

交接日期：2026-08-24
工作区：`/home/w417/RTAB-Map`
主分支：`main`

## 1. 项目目标

在 Ubuntu 20.04 + RTX 4090 主机上，通过 Docker 提供 Ubuntu 22.04 + ROS 2 Humble，
使用 TurtleBot3 Waffle、模拟 RGB-D 相机、RTAB-Map 和 Nav2 完成：

- 无真实 LiDAR 的室内点到点导航；
- RGB-D 在线建图与定位；
- 障碍物绕行和局部避障；
- 多目标逐段导航、闭环实验、轨迹图、时间和物理 contacts 记录；
- 后续迁移到真实 D435i 和真实底盘。

## 2. 当前已经做到什么

当前链路为：

```text
RGB-D 图像/深度
  -> RTAB-Map online SLAM -> /map、map->odom
  -> /nav_map + Nav2 global/local costmap
  -> GoalLineSmacPlanner / SmacPlanner2D
  -> Regulated Pure Pursuit (RPP)
  -> nav2_collision_monitor
  -> TurtleBot3 Waffle
```

自 2026-08-31 起，当前新实验和真实实车启动默认以四点闭环 v13
`adaptive_goal_line_050_recovery_v13_line_tiebreaker` 为工作基础；
`adaptive_goal_line_045` 只作为通用对照和旧动态场景历史 profile。large 场景 v4 的
固定世界坐标走廊不迁移到新场景或实车。

导航不是预先录制路线。每个目标段只发送目标坐标；规划器在当前实时 costmap 上重新
求解，目标线只是当前起点到当前目标的软偏好。Gazebo SDF 只用于物理仿真和轨迹图
绘制，不作为 Nav2 的先验路线。

## 6. 不要误解的边界

- `adaptive_goal_line_045` 是通用对照，不等于任意未知环境保证成功；当前新实验基础是
  四点闭环 v13。
- v4 包含 large 场景固定走廊先验，只用于历史 large benchmark，不能直接迁移真实环境。
- v13 仍是实时 RGB-D 建图和规划，但场景 02 的世界本身是静态仿真验收场景。
- Gazebo 无碰撞不等于真实 D435i 已验证；真实设备需要单独校准 TF、深度、底盘和急停。
- 不要为追求成功率关闭 collision monitor、缩小 footprint 或把失败轨迹改成成功。
