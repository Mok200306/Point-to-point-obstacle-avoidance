## 2. 一次正式 run 应保存

- `metrics.yaml`：整体/分段状态、耗时、轨迹长度、末端误差、contacts；
- `trajectory_comparison.png`：左 Gazebo 真值、右 RViz/costmap 风格；
- `trajectory.png`；
- 在线规划轨迹和 Gazebo 真值 CSV；
- `实验参数.yaml`、`导航参数.yaml`、`碰撞监视参数.yaml`；
- `世界文件.sdf`；
- Gazebo contacts 原始/过滤结果。

目录整理只移动 Git 中的结果目录，不改写实验当时生成的 `metrics.yaml`、`实验参数.yaml`
等原始快照中的 `label` 字段；这些字段保留实际运行时使用的旧 label。查找当前文件时以
本规则、`results/README.md` 和文件系统的新归档路径为准，不要把快照中的 label 当作当前
目录名。

## 3. 成功判定

只有同时满足以下条件才统计为成功：

1. `overall_succeeded: true`；
2. 每个目标段 `nav2_status: 4`；
3. `gazebo_non_ground_contact: false`，且 `gazebo_contact_pairs: "(none)"`；
4. 末端误差和轨迹文件存在；
5. 当前 profile、世界和 Git commit 可追溯。

`status=6` 即使没有碰撞，也只能记为安全停止/导航失败。`status=4` 但有非地面
contact，也不能记为无碰撞成功。

## 4. 保存和删除规则

- 正式三次结果不能复用 `run_01..run_03`；新实验用日期时间 label。
- 失败结果可以进入历史参考或阶段分析，但不能混入正式平均值。
- 清理前必须先读取 `metrics.yaml`，明确保留/删除名单。
- 删除的 Git 跟踪结果可从整理前 commit 恢复；没有 commit 的临时文件不保证可恢复。
- 结果目录整理不修改源码和世界文件，复现实验应以结果内参数快照和当前 commit 为准。
